03

Outlet registration flow

The registration flow is initiated by a GT sales user from within the GT app. The outlet's core information (name, address, type, distributor mapping) already exists in the FA outlet master — the registration step captures only the loyalty-specific KYC information required to enable the outlet for rewards.

Registration steps

1
GT user selects the outlet
User opens the loyalty section in the GT app and selects the outlet they want to register. Outlet master data (name, address, type, distributor) is pre-loaded — the user does not re-enter it.
2
KYC details captured
The user captures the outlet's KYC information as configured by the admin — documents and data fields required for verification are defined in the admin configuration. A third-party KYC API verifies the submitted information in the background.
3
Campaign selection (optional)
The user can optionally select one or more loyalty campaigns to enroll the outlet in at this stage. If no campaign is selected, the outlet will be registered only — enrollment can happen separately later.
4
Request submitted for approval
The registration request — including KYC data and any selected campaigns — is submitted. It enters the manager approval queue automatically via the Approval Mechanism (Registration approval type).
5
Manager reviews and decides
The manager sees the outlet details, KYC verification status, and the requested campaigns. They can approve, reject, or modify the campaign selection before approving. This is the only approval flow in the system where the approver can edit the request — specifically campaign selection only.
6
Outlet registered (and optionally enrolled)
On approval, outlet status moves to Registered. If campaigns were part of the approved request, the outlet is simultaneously enrolled and status moves to Enrolled. If the request is rejected, the outlet remains Not Registered and the GT user is notified.
Key distinction — manager edit rights

Registration approval is the only approval type in this system where the manager can modify the request — specifically the campaign selection. All other approval flows in the loyalty module are approve-only with no edit capability. This distinction is intentional and should be reflected in the approval configuration.

KYC configuration

The specific documents and data fields required during KYC are configured by the admin user — not hardcoded in the flow. The admin defines which documents must be uploaded and which fields must be filled before a registration request can be submitted. This allows the KYC requirements to be tailored per company or program without any development change.

04

Standalone campaign enrollment

For outlets that are already Registered but not yet Enrolled in a campaign, the GT user can raise a standalone campaign enrollment request. This flow is separate from the registration flow and follows its own approval type configured by the company.

1
GT user opens a registered outlet
From the loyalty dashboard or call prep screen, the user selects a Registered outlet and initiates campaign enrollment.
2
Campaign selected
User selects one or more active campaigns to enroll the outlet in. Only campaigns for which the outlet is eligible (based on cohort configuration) are shown.
3
Enrollment request submitted for approval
Request enters the approval queue via the Approval Mechanism — using the Campaign Enrollment approval type (separate from the Registration approval type). The approval hierarchy and rules are configurable by the company.
4
Outlet status → Enrolled
On approval, the outlet is enrolled in the selected campaigns. Status updates to Enrolled. Points calculation, reward slabs, and the full loyalty engine are now active for this outlet under the enrolled programs.
Eligibility

Which outlets are eligible for loyalty registration and which campaigns they can be enrolled in is controlled by the Admin using the Cohort configuration. The GT user only sees outlets and campaigns for which the outlet qualifies — eligibility filtering is handled by the system, not the user.

05

Approval mechanism

The onboarding flow uses the same underlying Approval Mechanism framework used across the loyalty module. Two distinct approval types are configured for onboarding — one for outlet registration and one for campaign enrollment. Each type has its own rules, hierarchy, and behaviour configured independently by the company.

Registration approval type
  • Triggered on registration request submission
  • Travels through FA manager hierarchy (L1/L2)
  • Manager can approve, reject, or modify campaigns
  • Multi-level support based on company config
  • Rejection returns outlet to Not Registered state
Campaign enrollment approval type
  • Triggered on standalone enrollment request
  • Separate approval rules configured by company
  • Uses same FA hierarchy
  • Approve only — no campaign modification at this stage
  • Rejection keeps outlet in Registered state
Approval type Approver actions Outcome on approval Outcome on rejection
Registration Approve · Reject · Modify campaigns Outlet → Registered (or Enrolled if campaign included) Outlet remains Not Registered
Campaign enrollment Approve · Reject Outlet → Enrolled in selected campaigns Outlet remains Registered only
Note

Approval type configuration — including hierarchy rules, number of levels, and role assignments — will be detailed as part of the development phase. The framework is shared across the loyalty module; only the configuration differs per approval type.

06

GT user dashboard

The GT user has a dedicated loyalty dashboard in the GT app that gives them a complete picture of outlet loyalty status across their territory — how many outlets are eligible, how many are already registered or enrolled, and the current state of all pending requests.

Dashboard metrics

MetricDescriptionSource
Total eligible outlets Outlets in the GT user's territory that qualify for loyalty based on admin cohort configuration. Cohort definition
Already registered Outlets with status Registered or Enrolled — loyalty has been enabled. Loyalty status master
Enrolled in campaigns Outlets currently active in at least one loyalty campaign. Loyalty status master
Pending requests Registration or enrollment requests raised by this GT user that are awaiting manager action. Approval request queue
Not yet registered Eligible outlets for which no registration request has been raised — representing the remaining opportunity. Cohort vs status delta

Request tracking section

Within the dashboard, the GT user can navigate to a Request section that shows all registration and enrollment requests they have raised. Each request shows its current status in the approval queue.

StatusWhat it means
Pending Request has been submitted and is awaiting manager action at the current approval stage.
In Progress At least one approval stage has been cleared; request is awaiting the next level of approval.
Approved All approval stages cleared. Outlet status has been updated accordingly.
Rejected Request has been declined by a manager. GT user can view the reason and raise a new request if needed.
07

Call prep screen — loyalty view

On the outlet call preparation screen in the GT app, a dedicated Loyalty CTA is displayed for every outlet. This gives the GT user a complete picture of the outlet's loyalty position before a visit — enabling informed, loyalty-led sales conversations.

Entry point

A Loyalty CTA appears on the call prep screen regardless of the outlet's current loyalty status. The label and content behind the CTA adapts based on status — giving the GT user the right information and the right next action at every stage.

Outlet status CTA behaviour What the GT user sees on tap
Not Registered Register for Loyalty Opens the registration flow directly. GT user can complete KYC and submit the request from here.
Registered Enroll in Campaign Shows loyalty status confirmation. Offers option to raise a campaign enrollment request.
Enrolled View Loyalty Full loyalty view — all active campaigns, targets, current achievement, points earned, slab progress, and reward structure. Identical to the retailer view.

Enrolled outlet — full loyalty view

When the outlet is Enrolled, tapping the Loyalty CTA opens a comprehensive view of the outlet's loyalty activity. This view mirrors what the outlet sees in their own retailer app — giving the GT user the same visibility as the outlet owner.

Program information
  • Active campaign names and period
  • Program type (base, multiplier, quarterly, annual)
  • Campaign start and end dates
  • Reward structure and slab details
  • Target for each enrolled campaign
Live performance data
  • Current achievement against target
  • Achievement percentage
  • Points earned to date in this period
  • Current slab the outlet is in
  • Points in process (pending approval)
Designed for sales conversations

The loyalty view in call prep is designed to equip the GT user with precise, real-time knowledge before engaging the outlet owner. With visibility into current achievement and slab position, the GT user can have a targeted conversation about what the outlet needs to do to reach the next reward tier. Automated nudges and recommendations are planned for a future phase.
